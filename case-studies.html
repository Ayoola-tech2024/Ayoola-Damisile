Cryptographic Security Engineering

@damisile_ayoola/envvault

Zero-Dependency AES-256-GCM Secret Management with In-Memory Process Injection

v1.1.0 npm package GitHub

Threat Vector & Problem

Plaintext .env files are notoriously vulnerable to accidental staging (git add .), TOCTOU (Time-of-Check to Time-of-Use) filesystem tampering, and cold storage swap extraction. Most secrets tooling requires heavy cloud runtime daemons or leaves temporary decrypted artifacts on disk.

Architectural Solution

A zero-dependency CLI written strictly atop Node's native crypto module. Uses PBKDF2 (SHA-512, 100,000 iterations) for key stretching, authenticated AES-256-GCM for ciphertext and tag generation, and child process in-memory IPC injection (process.env) so plaintext passwords never touch the filesystem.

Component Specification & Implementation Security Rationale
Symmetric Cipher AES-256-GCM (Authenticated Encryption with Associated Data) Prevents bit-flipping attacks via mandatory 128-bit GHASH authentication tag validation before decryption.
Key Derivation (KDF) PBKDF2-HMAC-SHA512 (100,000 iterations, 32-byte cryptographically secure random salt) Resistant to high-speed GPU/ASIC rainbow table dictionary attacks. Compliant with NIST SP 800-132 recommendations.
Process Injection child_process.spawn with ephemeral in-memory environment dictionary Eliminates disk I/O vulnerabilities (tempfiles, swap file dumping, inode retention). Passwords exist exclusively in child process virtual memory.
Pre-Commit Security Linter envvault audit + automated Git hook injection into .git/hooks/pre-commit Inspects git staged index via entropy heuristics and regex patterns to proactively block raw API tokens before git push.

fixmcp

Autonomous JSON-RPC 2.0 Stdio Diagnostic Doctor & Configuration Repair Utility

v0.1.0 npm package GitHub

Protocol Failure Mode

Model Context Protocol (MCP) clients (Claude Code, Cursor, Windsurf, VS Code) spawn server subprocesses via stdio. Configurations are fractured across OS-specific JSON files. When a server crashes or times out (error -32001) due to npx @latest registry round-trips or invalid JSON schemas, AI clients fail silently at boot without informative stack traces.

Diagnostic Engine

Discovers configs across 6 major AI agent environments, validates JSON syntax, and spawns real stdio sub-processes to execute active JSON-RPC 2.0 handshakes (initialize & tools/list). Times latency, counts registered capabilities, and provides an idempotent --fix runner that creates automated backups and normalizes paths.

checkIn — Biometric & Geofenced Attendance System

Production Platform for the School of Logistics and Innovation Technology (FUTA SLIT)

Production Live Application →

Real-World Constraints

University lecture halls with 200+ students encounter major failure points: hardware fingerprint queues take 45+ minutes, buddy-punching (proxy attendance) undermines trust, and unstable cellular/Wi-Fi connectivity causes high network dropped-packet rates when submitting data to cloud backends.

Multi-Tier Verification Architecture

Decentralizes verification to student smartphones. Extracts 468 3D facial landmarks directly on the client using WebAssembly MediaPipe (zero video streaming over network, preserving bandwidth and privacy), enforces a 50m Haversine GPS fence around the lecturer, and stores check-ins inside an offline IndexedDB queue with automatic background sync.

Mathematical Verification Models
1. Haversine Spatial Geodesic Distance Formula:

Calculates great-circle distance between student GPS coordinate $(lat_1, lon_1)$ and lecturer coordinate $(lat_2, lon_2)$: 

a = sin²(Δlat/2) + cos(lat₁) · cos(lat₂) · sin²(Δlon/2)
c = 2 · atan2(√a, √(1−a))
d = R · c  (where R = 6,371,000 meters)

Threshold Assertion:
d <= 50.0m  ──>  GPS Boundary Verified
d >  50.0m  ──>  Location Spoofing Rejected
2. 468-Landmark Topology Similarity Thresholding:

Cosine similarity across 3D normalized landmark vectors $\mathbf{u}$ and $\mathbf{v}$: 

Similarity = (u · v) / (||u|| ||v||)

3-Tier Decision Matrix:
• Similarity >= 0.50  ──> Verified Present (Instant Success)
• 0.40 <= Sim < 0.50  ──> Flagged for Manual Admin Review
• Similarity < 0.40   ──> Fraud Rejection (Identity Mismatch)
